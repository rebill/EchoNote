## 2. 背景

EchoNote v0.1 到 v0.9 是 Obsidian 插件，并依赖 Companion 桌面程序和本地 Python ASR 服务。这套方案有以下问题：

- 用户要同时安装和维护 Obsidian、插件、Companion、Python 虚拟环境和模型，任何一环出错都无法录音。
- 只在 macOS 上提供完整的录音链路。Windows 只有无界面的 CPU ASR 服务，以及基于 Audacity 导出文件的 VS Code 扩展方案。
- 录制线上会议要另装 BlackHole 或 Loopback 虚拟声卡。
- 音频在插件里编码成 WAV，经 HTTP 上传给 Python 服务。每个分段都要经过编码、写临时文件、multipart 解析和模型调用。

v1.0.0 改为一个独立应用，替代上述所有产品形态。

## 3. 产品定位

一句话描述：打开就能录、在本机实时转写、会后用你自己选的大模型生成纪要的会议记录应用。

目标用户：

- 经常开线上或线下会议、访谈、课程，需要文字记录的个人用户。
- 不希望会议音频上传到云端转写服务的用户。
- 已经有大模型 API（OpenAI 兼容服务、Anthropic、本地 Ollama）并希望自己选择服务商的用户。
- 使用 Obsidian 或其他 Markdown 工具管理笔记，需要导出纪要的用户。

## 4. 设计原则

1. **打开就能用**：安装包内置默认模型，没有设置向导。第一次录音时才申请系统权限，第一次使用 AI 功能时才配置服务商。
2. **一个主操作**：主界面只有一个"开始录音"按钮，另有全局快捷键和托盘入口。其余设置放在默认折叠的高级设置里。
3. **本地优先**：音频和转录只保存在本机。只有用户主动触发 AI 功能时，转录文本才会发给用户配置的 LLM 服务商，界面会写明接收方。
4. **低配可用**：4 核 CPU、8 GB 内存、没有独显的机器也要能实时转写。具体指标见第 8 节。
5. **不丢数据**：崩溃、断电或强制退出时，最多丢失正在说的那一句。

## 5. v1 范围

### 5.1 包含

| 模块 | 内容 |
|---|---|
| 平台 | macOS 14.2+（Apple Silicon、Intel），Windows 10/11 x64 |
| 录音 | 麦克风和系统音频分两轨同时采集，不依赖虚拟声卡。支持暂停、继续、停止和静音自动停止 |
| 实时转录 | 本地 ASR。录音时先显示预览文字，句子结束后替换为定稿 |
| 说话方 | 麦克风轨标记为"我"，系统音频轨标记为"对方"。系统音频轨没有语音时不显示标签 |
| 资料库 | 应用内会议列表，支持全文搜索（含中文子串）、重命名、删除 |
| 回放 | 默认保存压缩录音。点击任意一句转录可跳转回放 |
| 编辑 | 逐段编辑转录文本，可回退到原始识别结果 |
| 词表 | 一份用户词表，同时用于规则替换、高精度模型热词和 LLM 纠错提示 |
| 导出 | Markdown、TXT，记住上次导出的文件夹（可以是 Obsidian 库） |
| AI 总结 | 一键生成，输出为流式结果。内置通用会议、周会、访谈、课程模板，支持自定义模板。自动生成标题 |
| 会后问答 | 针对单场会议提问，回答带可点击的时间戳引用 |
| LLM 纠错 | 会后修正专有名词和同音错字，显示差异，可逐段接受或回退 |
| 会中要点 | 录音界面可开启，默认关闭。每 3 分钟增量更新要点 |
| LLM 接入 | OpenAI 兼容接口（附常用服务商预设）和 Anthropic Messages 接口。密钥存系统钥匙串 |
| 高精度模型 | 设置中按需下载 Qwen3-ASR，用于会后重新转写 |
| 界面语言 | 简体中文（默认）、英文 |

### 5.2 不包含（v1）

- 多人说话人分离：只按音轨区分"我"和"对方"，留到 v2。
- 账号、云同步、团队协作、分享链接。
- 移动端、Linux、Windows ARM64。
- 自动检测会议开始并自动录音。
- 导入旧版 Obsidian 会议笔记。
- 正式代码签名与公证：暂无证书，v1 先自用或源码分发。
- 遥测和使用统计。
- 音频以外的媒体导入（视频字幕、播客 RSS 等）。导入本地音频文件做离线转写可作为 v1 之后的增量。
- 由应用托管或代付的 LLM 服务。
## 6. 主要流程

### 6.1 第一次录音

1. 用户安装并打开应用，看到空的会议列表和"开始录音"按钮。
2. 点击后，应用立即开始采集麦克风。macOS 弹出麦克风权限和系统音频录制权限请求；Windows 只在麦克风隐私开关关闭时提示。
3. 如果用户拒绝系统音频权限，录音继续，只录麦克风；界面给出一行说明和"去系统设置开启"的链接。
4. 录音界面显示计时、两轨电平、实时转录。预览文字为灰色，定稿后变为正常颜色。
5. 用户点击停止，应用在 3 秒内把剩余音频转完，然后打开这场会议的详情页。

### 6.2 第一次生成总结

1. 用户在会议详情页点击"总结"。
2. 如果还没配置 LLM，就在同一个面板里选服务商预设，填 API Key（Ollama、LM Studio 不需要），点"测试连接"。
3. 连接成功后立即开始生成，结果以流式方式显示。面板顶部注明"转录将发送给 {服务商} / {模型}"。
4. 生成完成后，标题自动更新为模型给出的会议主题，用户可修改。

### 6.3 会后

- **问答**：在"问答"页签输入问题，回答里的 `[12:34]` 可点击跳转到对应时间并开始回放。
- **纠错**：在"转录"页签点击"AI 纠错"，修改的段落高亮显示，可逐段接受或回退，也可全部接受。
- **导出**：选择 Markdown 或 TXT，默认导出到上次的文件夹。
- **高精度重转**：已下载高精度模型时，可对整场录音重新转写；完成后保留旧版本，可回退。

## 7. 验收标准

| 编号 | 场景 | 标准 |
|---|---|---|
| A1 | 全新安装后录音 | 不联网、不做任何设置即可录音并实时转写 |
| A2 | 线上会议（耳机） | 对方声音来自系统音频轨，标签为"对方"；我的发言标签为"我" |
| A3 | 线上会议（外放） | 麦克风录到的对方声音不重复出现在"我"的转录中，误删率见技术方案门禁 |
| A4 | 线下会议 | 只有麦克风轨有内容，不显示说话方标签 |
| A5 | 强制退出 | 重新打开后会议仍在列表中，录音和转录保留到退出前最后一句 |
| A6 | 3 小时会议 | 内存不增长，转录列表滚动流畅，停止后 3 秒内完成 |
| A7 | 中英混说 | 中文和英文单词都能识别；搜索能找到中文子串和英文单词 |
| A8 | 拒绝系统音频权限 | 只录麦克风，不报错，不阻塞录音 |
| A9 | 切换音频设备 | 录音中插拔耳机或切换蓝牙设备，录音不中断，时间轴连续 |
| A10 | LLM 不可用 | 断网、密钥错误、限流时给出可理解的错误，转录和录音不受影响 |
| A11 | 长会议总结 | 超出模型上下文的转录自动分段总结后合并，不报错 |
| A12 | 删除会议 | 同时删除录音文件、转录、总结和问答记录 |

## 8. 非功能需求

性能目标（低配基线：4 核 CPU、8 GB 内存，无独显）。M0 实测后冻结到 `v1-performance-budgets.json`：

| 指标 | 目标 |
|---|---|
| 按下录音到开始采集 | < 300 ms |
| 冷启动到可交互 | < 1.5 s |
| 开始说话到出现预览（p95） | ≤ 1.0 s |
| 句尾到出现定稿（p95） | ≤ 1.5 s |
| 双轨录音时整机 CPU 平均占用 | ≤ 15% |
| 录音时内存（默认模型） | ≤ 500 MB |
| 托盘空闲时 CPU / 内存 | < 0.5% / < 150 MB |
| 停止录音到转录全部落库 | ≤ 3 s |
| 安装包大小 | ≤ 300 MB |

隐私与安全：

- 不收集遥测，不上传音频。
- API Key 只存系统钥匙串（macOS Keychain、Windows Credential Manager），不写入日志和数据库。
- 日志不记录转录内容。
- 删除会议时同时删除所有相关文件。

## 9. 与旧产品的关系

- `plugin/`、`companion/`、`asr-service/`、`vscode-extension/` 冻结，不再增加功能。v1 发布后移除，移除前单独确认。
- 旧版会议笔记仍在用户的 Obsidian 库中，v1 不导入。
- v1 的 Markdown 导出格式与旧版会议笔记结构相近（标题、元信息、总结各节、带时间戳的转录），方便在 Obsidian 中继续使用。
